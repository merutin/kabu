# 株式売買判断プログラム 設計検討

作成日: 2026-11-12
ステータス: フェーズ 0〜2 を初期実装済み（2026-11-12）。決定事項は 11 章

## 1. 目的と前提

| 項目 | 内容 |
|---|---|
| 目的 | 特定銘柄（最大 5 銘柄）について、売り / 買い / 様子見 を判断する |
| 保有期間 | 短期売買ではなく、1 ヶ月〜1 年程度の保有 |
| 最大化する対象 | **トータルリターン** = 株価値上がり益 + 配当金 + 株主優待 |
| 対象市場 | 日本株（東証）を想定。優待があるのは日本株のみのため |
| 利用形態 | 個人利用。定期的（週 1 回程度）に実行し、判断結果を確認する |

### 1.1 最初に押さえておきたい前提

* **株価そのものを正確に予想することはできない。** 1 ヶ月〜1 年先の株価を当てるモデルは、プロでも安定して作れていない。
  本プログラムでは「株価予想」を **期待リターンのレンジ（幅）と根拠の提示** として扱い、点推定の数字を信じ込まない設計にする。
* 一方で **配当と優待は、権利確定日・金額・条件がほぼ確定情報** であり、プログラムで正確に計算できる。
  → 判断ロジックの土台は「確度の高いインカム（配当 + 優待）」に置き、株価部分は補正・リスク評価として扱うのが現実的。
* 銘柄数が 5 以下なので、**優待情報などは手動メンテナンス（YAML）で十分**。スクレイピングで無理に自動化しない。

## 2. 判断の考え方（トータルリターンの定義）

保有期間 H（例: 6 ヶ月）における期待トータルリターンを次のように定義する。

```
期待トータルリターン(H)
  = 株価リターン(H)                       … 不確実。レンジで推定
  + Σ 配当(H 内に権利確定日があるもの)        … ほぼ確定（会社予想ベース）
  + Σ 優待換算額(H 内に権利確定日があるもの)   … ほぼ確定（継続保有条件を満たす場合のみ）
  − 売買コスト − 税金
```

利回りに直す場合は、取得単価（または現在株価）× 必要株数 で割る。

### 2.1 優待・配当ならではの考慮点

| 論点 | 内容 | プログラム上の扱い |
|---|---|---|
| 権利確定日 | 配当・優待は権利確定日（月末が多い）に株主名簿に載っている必要がある。権利付き最終日はその 2 営業日前 | カレンダー計算が必須。保有期間内に何回権利確定日を跨ぐかで期待リターンが大きく変わる |
| 配当落ち・優待落ち | 権利落ち日に株価は理論上その分下がる。優待人気銘柄は権利確定前に上がり、直後に下がる傾向 | 「権利落ち後に買う」などのタイミング評価を入れる |
| 継続保有条件 | 「1 年以上保有」「同一株主番号で 3 回連続記載」など、近年条件付きが増えている | **保有開始日と株主番号の連続性** を管理しないと、1 年未満の保有では優待ゼロになる。売却判断時に「今売ると優待条件がリセットされる」を警告 |
| 必要株数 | 100 株で優待、1,000 株で優待が増える、など段階制 | 優待利回りは「保有株数」に応じて計算する |
| 優待の価値 | 金券なら額面に近いが、自社商品・割引券は人によって価値が違う | 「市場価値（金券ショップ換金率など）」と「自分にとっての価値（係数）」の両方を持たせる |
| 優待の改悪・廃止 | 発表当日に株価が大きく下がることが多い | 直接予測は不可能。業績悪化・配当性向の異常・大株主の変化などをリスク指標として警告 |
| 税金 | 配当は 20.315%（NISA なら非課税）。売却益も同率。優待は実務上課税されないことが多い | NISA 口座かどうかを設定で持つ |

## 3. 必要なデータ

### 3.1 データ一覧

| # | データ | 用途 | 主な取得元 | 更新頻度 | 備考 |
|---|---|---|---|---|---|
| 1 | 株価（日足 OHLCV、数年分） | 株価リターン推定、トレンド、ボラティリティ、バックテスト | J-Quants API / yfinance（`7203.T` 形式） | 毎日〜週次 | yfinance は無料だが非公式。J-Quants は JPX 公式で有料プランあり |
| 2 | 配当実績・配当予想（1 株あたり） | 配当利回り、インカム計算 | J-Quants 財務情報（決算短信の予想配当）/ yfinance / 会社 IR | 四半期ごと | 会社予想の修正に注意 |
| 3 | 権利確定日・権利付き最終日 | 保有期間内のインカム計算、売買タイミング | 会社 IR（決算期から算出可能）+ 東証営業日カレンダー | 年次 | 中間配当の有無も銘柄ごとに持つ |
| 4 | 優待情報（内容、必要株数、権利確定月、換算額、継続保有条件） | 優待利回り、継続保有管理 | **手動 YAML**（会社 IR を正とする） | 変更時 | 公式 API はない。5 銘柄なら手動で十分 |
| 5 | 財務指標（EPS、BPS、PER、PBR、ROE、配当性向、売上・利益推移、業績予想） | 割安 / 割高判定、減配・優待廃止リスク | J-Quants 財務情報 / EDINET API / yfinance | 四半期ごと | PER・PBR は自社の過去レンジとの比較が主用途 |
| 6 | イベント日程（決算発表日、株式分割、優待変更発表） | 決算直前の売買回避、分割後の株数補正 | 会社 IR / J-Quants | 随時 | |
| 7 | 市場指数（TOPIX、日経 225）、為替（USD/JPY） | 市場全体との相対比較（相対強度）、バックテストのベンチマーク | yfinance / J-Quants | 毎日 | 任意。最初は TOPIX のみで十分 |
| 8 | 自分のポートフォリオ（保有株数、取得単価、取得日、口座種別、現金） | 損益計算、継続保有判定、売却判断 | **手動 YAML** | 売買時 | 取得日が優待の継続保有条件判定に必須 |
| 9 | 売買コスト（手数料、スプレッド想定） | 期待リターンからの控除 | 設定ファイル | 固定 | |

### 3.2 取得元の比較

| 取得元 | 費用 | 良い点 | 注意点 |
|---|---|---|---|
| yfinance | 無料 | 導入が最も簡単。株価・配当実績・簡易指標が取れる | 非公式ライブラリ。仕様変更・取得失敗がときどき起きる。配当予想は無い |
| J-Quants API（JPX 公式） | 無料プランあり（直近データに遅延）、有料プランで遅延なし | 公式データ。財務情報（決算短信ベース、予想配当・予想 EPS を含む）が取れる | 料金・プラン内容は変わるため公式サイトで要確認。配当金情報エンドポイントは上位プラン限定 |
| EDINET API | 無料（API キー要） | 有価証券報告書などの一次情報 | XBRL の解析が重い。最初は不要 |
| 会社 IR ページ | 無料 | 優待・配当方針の一次情報 | 手動確認が前提 |
| 優待情報サイト（かぶ優待、みんかぶ等） | 無料 | 換算額の目安 | スクレイピングは利用規約上避け、手動で転記する |

**推奨**: まず yfinance で株価・配当実績を取り、優待・権利確定日・予想配当は手動 YAML。精度や安定性が必要になった段階で J-Quants に切り替える（取得層を差し替えられる設計にしておく）。

### 4.1 各コンポーネントの役割

| 記号 | コンポーネント | 作るもの | 優先度 |
|---|---|---|---|
| A | データ取得層 | 株価・配当・財務の取得とキャッシュ。取得元を差し替えられるインターフェース | 高 |
| B | インカム計算 | 保有期間内の配当・優待の合計額。継続保有条件、必要株数、税引後計算 | **最高**（確度が高く、価値が大きい） |
| C | 株価評価 | 割安度（自社過去レンジでの PER/PBR/配当利回り位置）、トレンド、リスク指標 | 高 |
| D | 判定 | B と C を合成して期待トータルリターンのレンジを出し、閾値で BUY/HOLD/SELL。**理由を必ず文章で出す** | 高 |
| E | バックテスト | 判定ルールを過去数年に適用し、配当・優待込みで「買って持ち続ける」や TOPIX と比較 | 中（ルール導入前に必須） |
| F | 保有管理 | 現在の損益、受取済みインカム、優待条件までの残り日数 | 中 |
| G | 出力・通知 | 週次レポート。GitHub Actions で定期実行 | 低（後回し可） |

## 5. 判定ロジック案

### 5.1 スコアの構成

1. **インカム利回り（年率換算）**
   `(年間予想配当 × 税率補正 + 優待換算額 × personal_factor) / (株価 × 必要株数)`
   → 保有期間 H 内に実際に取れる分だけを計上する（権利確定日と継続保有条件で判定）。
2. **割安度**
   現在の PER / PBR / 配当利回りが、自社の過去 3〜5 年レンジのどこに位置するか（パーセンタイル）。
   割安なら株価リターンの期待値をプラス方向、割高ならマイナス方向に補正。
3. **トレンド**
   200 日移動平均との位置、12 ヶ月モメンタム（直近 1 ヶ月を除く）、TOPIX 比の相対強度。
   長期トレンドが下向きの銘柄は「インカムが良くても様子見」に倒す。
4. **リスク**
   ボラティリティ、最大ドローダウン、配当性向の異常（100% 超など）、業績予想の下方修正。
   減配・優待廃止の可能性が高い状態を減点。
5. **タイミング**
   権利付き最終日までの日数、決算発表日との近さ。
   「権利落ち直後で割安」「決算 3 日前なので待つ」などを判定理由に含める。

### 5.2 判定ルール（初期案）

| 判定 | 条件（例） |
|---|---|
| BUY | 期待トータルリターン（H）の下限 > 0 かつ中央値 > 設定閾値（例: 年率 5%）、トレンドが下向きでない、決算直前でない |
| HOLD | 保有中で、売却すると優待の継続保有条件がリセットされる、または期待リターンがプラス |
| SELL | 期待トータルリターンの中央値 < 0、または割高（過去レンジ上位 10%）かつトレンド反転、または減配・優待改悪の発表 |
| WAIT | 判定材料が不足、決算発表直前、権利落ち直前（買う場合は落ち後まで待つ） |

閾値は `settings.yaml` で調整可能にし、バックテストで決める。

### 5.3 出力例（Markdown）

```
## XXXX サンプル株式会社   判定: BUY（信頼度: 中）
- 現在株価 2,480 円 / 100 株 = 248,000 円
- 6 ヶ月の期待トータルリターン: +2.1% 〜 +9.4%（中央値 +5.6%）
  - 配当: 3 月権利 25 円 × 100 株 = 2,500 円（NISA のため非課税）
  - 優待: 3 月権利 自社商品券 1,000 円（継続保有条件なし）
  - 株価: PER 11.2 倍は過去 5 年の下位 20%。200 日線より上
- リスク: 配当性向 45%（健全）。次回決算 2 月 10 日
- 補足: 権利付き最終日 3 月 27 日。それ以前に買えば今期の配当・優待を取れる
```

## 6. バックテスト

* 過去 5〜10 年の日足に対し、毎月（または毎週）判定を実行し、その通り売買した場合の損益を計算する。
* **配当・優待を含める**（権利確定日に現金相当として加算。優待は market_value × 換算率）。
* 比較対象: 「買って持ち続ける」「TOPIX 連動 ETF」「配当・優待だけ取ってすぐ売る」。
* 評価指標: 年率リターン、最大ドローダウン、勝率、取引回数（手数料負けの確認）。
* 注意: 5 銘柄・数年分では統計的に十分とは言えない。**ルールが明らかに有害でないことの確認** が目的で、優位性の証明ではない。
* 将来的に機械学習（LightGBM など）を試すとしても、まずルールベースでバックテストできる基盤を作ってから。

## 7. 技術スタック案

| 項目 | 選択 | 理由 |
|---|---|---|
| 言語 | Python 3.12 | データ取得・分析ライブラリが最も揃っている |
| パッケージ管理 | uv（または poetry） | 再現性のある環境 |
| データ処理 | pandas | 日足・財務データの標準 |
| データ取得 | yfinance（初期）→ jquants-api-client（必要時） | 取得層を抽象化して切替可能に |
| 保存 | SQLite または parquet | ローカル完結、API 呼び出しの節約 |
| 設定 | YAML（pydantic でバリデーション） | 優待・保有情報を人が編集しやすい |
| テスト | pytest | 権利確定日計算・継続保有判定など、ロジックの単体テストが重要 |
| 定期実行 | GitHub Actions（cron） | サーバー不要。レポートをリポジトリにコミット or 通知 |
| 可視化 | 最初は Markdown テーブルのみ。必要なら matplotlib / Streamlit | 過剰な UI を作らない |

## 8. 開発ステップ

| フェーズ | 内容 | 成果物 |
|---|---|---|
| 0. 基盤 | リポジトリ構成、設定ファイル定義、対象 5 銘柄の `stocks.yaml` / `yutai.yaml` / `portfolio.yaml` 作成 | 設定ファイル、pydantic モデル |
| 1. インカム計算 | 株価・配当取得（yfinance）、営業日・権利付き最終日計算、期間内の配当・優待額の計算、継続保有判定 | `judge.py` で「各銘柄の総合利回り」が出る |
| 2. 株価評価と判定 | PER/PBR レンジ、トレンド、リスク指標、BUY/HOLD/SELL ルール、Markdown レポート | 週次レポート |

## 9. 決めていただきたいこと（→ 11 章で決定済み）

1. **対象銘柄**: 具体的な証券コード（最大 5）。優待の内容と条件も合わせて確認する。
2. **データ取得元**: 無料の yfinance から始めてよいか。J-Quants の有料プランを使う意思があるか。
3. **口座種別**: NISA か課税口座か（配当・売却益の税計算に影響）。
4. **優待の価値の決め方**: 市場換算額をそのまま使うか、自分が使う分だけ（係数）で割り引くか。
5. **保有期間 H の既定値**: 判定の基準期間（例: 6 ヶ月）。複数期間（3 / 6 / 12 ヶ月）を同時に出すことも可能。
6. **出力先**: ローカルで Markdown を見るだけでよいか、Slack / LINE / メール通知が欲しいか。
7. **言語**: Python で問題ないか。

## 10. 注意点・リスク

* 株価部分の予測精度は低い前提で設計する。プログラムの出力は **判断材料** であり、最終判断は人が行う。
* yfinance は非公式ライブラリのため、将来取得できなくなる可能性がある。取得層を差し替え可能にしておく。
* 優待情報は必ず会社 IR を一次情報として確認する。サイト情報は古いことがある。
* 優待の改悪・廃止、減配は事前予測がほぼ不可能。銘柄数が少ない分、1 銘柄のイベントの影響が大きい。
* バックテストは「過去にそうだった」以上のことを言わない。過剰にルールを最適化しない。
* 投資判断に関する法的助言ではなく、個人利用の分析ツールとして扱う。

## 11. 決定事項と実装状況（2026-11-12）

### 11.1 決定事項

| 論点 | 決定 | 実装への反映 |
|---|---|---|
| 対象銘柄 | 未定 | `config/stocks.yaml` / `config/yutai.yaml` はサンプル 1 銘柄。決まり次第差し替え |
| データ取得元 | 松井証券・GMOクリック証券の口座あり | 両社とも個人向けの **株式データ API は提供していない**（松井は FX 向け API のみ）。保有状況・優待情報の転記元として使い、株価は yfinance から取得。必要になれば J-Quants に差し替え可能な構造 |
| 口座 | NISA | `settings.account: nisa` → 配当税率 0%。`taxable` にすると 20.315% |

| 判定軸 | 複数軸、基本は半年〜1 年 | 3 / 6 / 12 ヶ月を同時に試算し、6 ヶ月と 12 ヶ月を最終判定に使用 |
| 出力先 | 通知が欲しい | Claude のスケジュールタスク（毎週土曜 08:44 JST）で実行し通知。Slack / Discord Webhook とメール（SMTP）にも対応 |

### 11.3 期待トータルリターンの計算式（実装）

```
株価リターン(H) 中央値 = (基礎期待 3% + 割安度補正 ±6% + トレンド補正 ±4%) × H/12
                       − 期間内の配当落ち分（配当はインカム側で計上するため）
幅               = ± 年率ボラティリティ × √(H/12)
インカム(H)       = Σ 税引後配当 + Σ 優待(market_value × personal_factor)
                   ※ 権利付き最終日 >= 判定日 かつ 権利確定日 <= 判定日+H の回のみ
                   ※ 優待は必要株数・継続保有条件を満たす回のみ
期待トータルリターン = 株価リターン + インカム − 往復手数料
```

係数（3% / 6% / 4%）はすべて `settings.yaml` で変更できる。フェーズ 3 のバックテストで調整する前提の暫定値。

### 11.4 判定ルール（実装）

| 状態 | 判定 | 条件 |
|---|---|---|
| 未保有 | BUY | 6 ヶ月・12 ヶ月ともに年率換算の中央値 ≥ 閾値（既定 5%）かつ下降トレンドでない |
| 未保有 | WAIT | 上記以外、または決算発表の前後 3 日以内 |
| 保有中 | SELL | 6 ヶ月・12 ヶ月ともに中央値がマイナス、または割高（利回りが過去レンジ下位 10%）かつ下降トレンド |
| 保有中 | HOLD | 上記以外。継続保有条件がある銘柄は売却時にリセット警告 |
